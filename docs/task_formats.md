# Форматы ввода и проверочные примеры

Все задачи запускаются отдельно: ./cpp/laba2 <номер> или cd go && go run . <номер>.

## 1. Порядок выполнения задач

Ввод: N M, затем N имён задач, затем M пар задача предшественник.

    3 2
    A B C
    A B
    B C

Ожидаемый ответ: Возможно. Если зависимости образуют цикл — Невозможно.

## 2. АТД «Множество»

Ввод пакетного режима: число команд Q, затем Q строк с командами SETADD x, SETDEL x, SET_AT x.

    5
    SETADD cat
    SET_AT cat
    SETDEL cat
    SET_AT cat
    SET_AT dog

Ожидаемый вывод: TRUE, FALSE, FALSE.

Также реализован запуск из методички: ./laba2 --file <путь> --query "SETADD x". Файл содержит исходные элементы множества, по одному на строку. SETADD и SETDEL сохраняют изменения в файл, SET_AT выводит TRUE или FALSE.

## 3. Инопланетный геном

Ввод: две строки заглавных латинских букв.

    ABBACAB BCABB

Ожидаемый ответ: 4. Повторяющиеся пары первого генома учитываются отдельно.

## 4. Контрольная по ударениям

Ввод: N, затем N слов словаря, затем одна строка текста. Заглавная буква обозначает ударение.

    4
    cAnnot
    cannOt
    fOund
    pAge
    thE pAge cAnnot be fouNd

Ожидаемый ответ: 2.

## 5. Проверка дерева

В методичке не задан способ передачи структуры дерева. В проекте принят формат обхода по уровням: значения узлов через пробел, # — отсутствующий узел. Вводится одна строка. После восстановления выводится дерево в том же формате. Связи между узлами не перестраиваются, меняются только значения двух узлов.

    6 2 8 # 4 5 #

Результат: 5 2 8 # 4 6.

## 6.1. Хеширование

Ввод: количество ключей N, простая ёмкость таблицы M (M не менее 3), затем N целых ключей. Для линейного пробирования и двойного хеширования выводятся число сохранённых различных ключей, число проверенных ячеек и время вставки в наносекундах. Для корректного полного цикла двойного хеширования размер таблицы должен быть простым.

    6 11
    10 21 32 43 54 65

## 6.2. Количество сотрудников

Ввод: N, затем N пар сотрудник менеджер. Самостоятельное подчинение обозначает корневого менеджера. Повтор одинаковой пары учитывается один раз. Если сотруднику указали разных менеджеров, программа сообщает об ошибке.

    5
    A B
    C B
    D E
    B E
    E E

Ожидаемый вывод:

    A 0
    B 2
    C 0
    D 0
    E 4

## 7. LRU-кэш

Ввод: ёмкость кэша, количество запросов Q, затем Q запросов SET x y или GET x.

    2 8
    SET 1 2
    SET 2 3
    SET 1 5
    SET 4 5
    SET 6 7
    GET 4
    SET 1 2
    GET 3

Ожидаемый вывод: 5 -1.

## Используемые структуры ЛР1

Стек — в задании 1; множество — в заданиях 2 и 3; динамический массив — в задании 4; двоичное дерево — в задании 5; двусвязный список — в задании 7. Для иерархии сотрудников используется открытая хеш-таблица из подзадания 6.1.
