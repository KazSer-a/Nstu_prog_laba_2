# Руководство пользователя

Программа выполняет одно задание за запуск. Обе реализации принимают одинаковые команды и форматы входных данных. Все приведённые команды выполняются из корневого каталога проекта.

## Сборка и ввод данных

Для сборки C++17 необходимы `g++` и `make`. Для второй реализации необходим Go версии 1.20 или новее.

```bash
make cpp    # Собрать исполняемый файл cpp/laba2
make go     # Собрать исполняемый файл go/laba2
make        # Собрать обе реализации
make clean  # Удалить исполняемые файлы сборки
```

После запуска `./cpp/laba2 3` программа ожидает две строки геномов. Их можно набрать в терминале, нажимая Enter после каждой строки, или перенаправить ввод из файла. Примеры ниже используют `printf`, чтобы передать готовые входные данные. Последовательность `\n` означает переход на новую строку. Для запуска таких же примеров на Go замените `./cpp/laba2` на `./go/laba2`.

```bash
./cpp/laba2 3 < input.txt
./go/laba2 3 < input.txt
```

| Аргумент | Режим |
|---|---|
| `1` | Порядок выполнения задач |
| `2` | АТД «Множество», пакетный режим |
| `3` | Инопланетный геном |
| `4` | Контрольная по ударениям |
| `5` | Восстановление двоичного дерева поиска |
| `6` | Сравнение методов разрешения коллизий, задание 6.1 |
| `7` | Подсчёт подчинённых, задание 6.2 |
| `8` | LRU-кэш, задание 7 |
| `--file <путь> --query "<команда>"` | АТД «Множество», одна команда с данными из файла |

Количество элементов, пар и команд указывается целым неотрицательным числом. Имена и строковые ключи в примерах состоят из одного слова. Команды `SETADD`, `SETDEL`, `SET_AT`, `SET` и `GET` записываются прописными буквами.

## Режим 1. Порядок выполнения задач

**Ввод.** Число задач `N` и зависимостей `M`, затем `N` имён задач и `M` пар. Пара `A B` означает, что задачу `B` требуется выполнить до `A`.

**Вывод.** `Возможно`, если существует допустимый порядок выполнения всех задач. При циклической зависимости выводится `Невозможно`.

```bash
printf '3 2\nA B C\nA B\nB C\n' | ./cpp/laba2 1
printf '3 3\nA B C\nA B\nB C\nC A\n' | ./cpp/laba2 1
```

Первый запуск выводит `Возможно`, поскольку задачи можно выполнить в порядке C, B, A. Во втором запуске зависимость C от A замыкает цикл, поэтому выводится `Невозможно`.

## Режим 2. АТД «Множество»

Множество хранит уникальные строковые ключи. Повторное добавление сохраняет один экземпляр ключа. Удаление отсутствующего ключа оставляет множество без изменений.

| Команда | Действие | Результат |
|---|---|---|
| `SETADD x` | Добавить ключ `x` | В пакетном режиме вывода нет. В файловом при успешном сохранении выводится `OK`. |
| `SETDEL x` | Удалить ключ `x` | В пакетном режиме вывода нет. В файловом при успешном сохранении выводится `OK`. |
| `SET_AT x` | Проверить наличие ключа `x` | `TRUE`, если ключ есть, иначе `FALSE`. |

### Пакетный режим

На вход подаются количество команд `Q` и затем `Q` команд. Множество в начале пустое, данные сохраняются на время одного запуска. Каждый результат проверки печатается на отдельной строке.

```bash
printf '5\nSETADD cat\nSETADD cat\nSET_AT cat\nSETDEL cat\nSET_AT cat\n' | ./cpp/laba2 2
```

```text
TRUE
FALSE
```

### Файловый режим

Аргумент `--file` указывает путь к текстовому файлу. Аргумент `--query` содержит одну команду с ключом, заключённую в кавычки. При добавлении или удалении программа сохраняет отсортированные ключи по одному на строку. Команда `SET_AT` читает данные и оставляет файл без изменений. Каталог, в который выполняется запись, должен существовать.

```bash
set_file=$(mktemp)
./cpp/laba2 --file "$set_file" --query "SETADD cat"
./cpp/laba2 --file "$set_file" --query "SET_AT cat"
./cpp/laba2 --file "$set_file" --query "SETDEL cat"
./cpp/laba2 --file "$set_file" --query "SET_AT cat"
rm "$set_file"
```

Ответы по порядку: `OK`, `TRUE`, `OK`, `FALSE`. В качестве файла можно также использовать `data/set.txt`.

## Режим 3. Инопланетный геном

**Ввод.** Две непустые строки из заглавных латинских букв.

**Вывод.** Число соседних пар первого генома, встречающихся во втором. Повтор пары в первом геноме учитывается при каждом вхождении. Достаточно одного вхождения пары во втором.

```bash
printf 'ABBACAB\nBCABB\n' | ./cpp/laba2 3
```

Результат — `4`. В первом геноме засчитываются пары `AB`, `BB`, `CA` и повторная пара `AB`.

## Режим 4. Контрольная по ударениям

**Ввод.** Число словарных записей `N`, затем `N` записей и одна отдельная строка проверяемого текста. Заглавная буква обозначает ударение. Несколько записей одного слова могут задавать разные допустимые позиции ударения.

**Вывод.** Число ошибочных слов. В слове должна быть ровно одна заглавная буква. Для словарного слова её позиция должна совпасть с одной из допустимых. Для слова вне словаря достаточно одной заглавной буквы.

```bash
printf '4\ncAnnot\ncannOt\nfOund\npAge\nthE pAge cAnnot be fouNd\n' | ./cpp/laba2 4
```

Результат — `2`. В слове `be` ударение отсутствует, а в `fouNd` указана позиция, которой нет в словаре.

## Режим 5. Восстановление двоичного дерева поиска

**Ввод.** Одна строка с ключами по уровням. Первое число — корень, далее идут левый и правый потомки существующих узлов по порядку. Символ `#` обозначает отсутствующего потомка. Конечные маркеры `#` можно опустить.

**Вывод.** Ключи восстановленного дерева в том же формате. Программа меняет значения двух узлов, сохраняя связи между ними. В восстановленном дереве слева от узла находятся строго меньшие ключи, справа — большие либо равные.

```bash
printf '6 2 8 # 4 5 #\n' | ./cpp/laba2 5
printf '2 2 1\n' | ./cpp/laba2 5
```

Первый запуск выводит `5 2 8 # 4 6`. Во втором проверяется обработка повторяющегося ключа, результат — `2 1 2`. Если перестановка не найдена или обмен не восстанавливает дерево поиска, программа выводит диагностическое сообщение.

## Режим 6. Сравнение методов разрешения коллизий

**Ввод.** Количество ключей `N`, ёмкость таблицы `M` и затем `N` целых ключей. Ёмкость должна быть простым числом и составлять не менее трёх ячеек.

**Вывод.** Для линейного пробирования и двойного хеширования печатаются число сохранённых различных ключей из `N`, общее число проверенных ячеек и время вставки в наносекундах. Повтор ключа участвует в подсчёте проб, сохраняя одну запись. Если места недостаточно, количество сохранённых ключей может быть меньше числа различных входных ключей.

```bash
printf '4 5\n1 1 6 11\n' | ./cpp/laba2 6
```

Оба метода сохраняют `3/4` ключей. Линейное пробирование проверяет `7` ячеек, двойное хеширование — `6`. Время зависит от компьютера и запуска. [Результаты эксперимента](hash_comparison.md)

## Режим 7. Количество сотрудников

**Ввод.** Количество пар `N`, затем `N` пар «сотрудник менеджер». Пара `A B` означает, что A подчиняется B. Пара `E E` обозначает сотрудника без вышестоящего руководителя.

**Вывод.** По строке на сотрудника в алфавитном порядке: имя и количество прямых и косвенных подчинённых. Повтор одинаковой пары учитывается один раз. Несколько разных руководителей у одного сотрудника и циклы в иерархии приводят к диагностическому сообщению.

```bash
printf '5\nA B\nC B\nD E\nB E\nE E\n' | ./cpp/laba2 7
```

```text
A 0
B 2
C 0
D 0
E 4
```

У B два прямых подчинённых. У E два прямых подчинённых, B и D, и два косвенных, A и C.

## Режим 8. LRU-кэш

**Ввод.** Ёмкость `C`, количество запросов `Q`, затем `Q` запросов. Ключи и значения — целые числа.

| Запрос | Действие | Вывод |
|---|---|---|
| `SET x y` | Сохранить значение `y` по ключу `x` или обновить существующую запись. Ключ становится самым недавно использованным. | Нет |
| `GET x` | Прочитать значение. При успешном чтении запись становится самой недавно использованной. | Значение или `-1`, если ключ отсутствует |

Если новый ключ добавляется в заполненный кэш, вытесняется запись, к которой дольше всего не обращались. Кэш нулевой ёмкости не сохраняет записи. Ответы на `GET` печатаются по порядку, через пробел.

```bash
printf '2 5\nSET 1 10\nSET 2 20\nGET 1\nSET 3 30\nGET 2\n' | ./cpp/laba2 8
```

```text
10 -1
```

Первый запрос `GET` обновляет порядок обращения к ключу 1. Поэтому вставка ключа 3 вытесняет ключ 2.
